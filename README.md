# TraceGuard — Adaptive Network Threat Detection

> **Stage 5 Complete: Full End-to-End Application Integration**  
> An adaptive network intrusion detection research prototype combining supervised classification, confidence calibration, unsupervised anomaly detection, and tri-state selective triage. Designed to evaluate unfamiliar zero-day attacks, changing traffic distributions, class imbalance, and predictive uncertainty.

> [!IMPORTANT]
> **Operational Status & Research Prototype Scope:** TraceGuard is an integrated **offline research application and demonstration prototype**, not a commercial or production Network Security Monitoring (NSM) system. Live network interface packet taps, kernel-level packet capture, and continuous production SOC stream monitoring are not implemented. The application processes pre-extracted 69-feature statistical flow vectors (such as those generated by CICFlowMeter) and transparently distinguishes frozen offline research baselines from active API telemetry.

## 1. Project Purpose & Research Question

Traditional Network Intrusion Detection Systems (NIDS) frequently rely on standard multi-class classifiers evaluated on synthetic benchmark datasets using raw accuracy. Under realistic network conditions, they fail in two critical ways:
1. **Unseen Zero-Day Attacks:** Novel attack variants not represented in the training set are silently misclassified as benign traffic.
2. **Traffic & Covariate Shift:** Changing network environments cause statistical feature distributions to shift, degrading detector reliability without warning.

### Core Research Question

> **"Can TraceGuard detect threats reliably when attack categories are unseen or network traffic changes, and can it recognize when it should not trust its own prediction?"**

TraceGuard addresses this by coupling a supervised Random Forest classifier with **confidence calibration (Platt scaling)**, **unsupervised anomaly detection (Isolation Forest)**, and a **selective prediction (abstention) triage policy**. Rather than forcing a binary or uncalibrated decision on ambiguous traffic, TraceGuard implements a three-way triage policy:
- **`THREAT_SUSPECTED`:** High calibrated probability of attack ($\ge 0.70$) or elevated anomaly score above policy threshold.
- **`ABSTAIN`:** Out-of-distribution traffic (high anomaly score with low classifier probability), high prediction uncertainty, or ambiguous flows. The flow is safely routed to SOC analysts for manual review.
- **`LIKELY_BENIGN`:** High calibrated benign confidence and low anomaly score. **Important:** Statistical resemblance to benign baseline traffic is *never* a guarantee of safety.

- **Security Guardrails:** Centralized exception handlers prevent stack trace or path disclosure; strict batch limits ($\le 500$ records); strict CORS; server-controlled model artifact loading; strict input validation with zero silent imputation.

## 4. Model Artifacts & Lifecycle Behavior

TraceGuard requires five trusted model artifacts in `models/artifacts/` produced by the frozen Stage 4.1 research training pipeline:
1. `stage4_preprocessor.joblib`: Preprocessing pipeline with exact 69-feature transformation and train-time median imputation.
2. `stage4_classifier.joblib`: Supervised Random Forest binary classifier trained on known attacks.
3. `stage4_calibrator.joblib`: Platt confidence calibrator (logistic sigmoid) fitted on `val_cal_df`.
4. `stage4_anomaly_detector.joblib`: Benign-only Isolation Forest anomaly detector.
5. `stage4_metadata.json`: Feature list, anomaly thresholds ($\tau_{5\%}=0.6001$, $\tau_{25\%}=0.1873$), and training provenance.

### Controlled Startup & Graceful Fallback
- **Single Load on Startup:** Artifacts are loaded once during application startup in the FastAPI lifespan handler, never per prediction.
- **Independence of Health and Model Readiness:** `GET /health` always returns HTTP 200 with service health `healthy`, even when models are not loaded.
- **Graceful Unconfigured Fallback:** If artifacts are missing or corrupt:
  - `GET /api/model/status` returns `lifecycle_status: UNCONFIGURED`.
  - `POST /api/model/predict` returns HTTP 503 (`MODEL_UNCONFIGURED`).
  - The React dashboard displays a clear, non-blocking warning without crashing.

## 5. Standardized 69-Feature Network Flow Schema

TraceGuard operates on 69 statistical flow features derived from bidirectional network flows:

| Category | Count | Key Features |
| :--- | :---: | :--- |
| **Transport & Addressing** | 2 | `Destination Port`, `Protocol` |
| **Duration & Packet Counts** | 3 | `Flow Duration`, `Total Fwd Packets`, `Total Backward Packets` |

| **Subflows & Idle Dynamics** | 20 | `Subflow Fwd/Bwd Packets/Bytes`, `Active Mean/Std`, `Idle Mean/Std/Max/Min` |

## 6. Supported Triage Policies

TraceGuard evaluates traffic against three documented, reproducible triage policies:

| Policy | Anomaly Threshold ($\tau$) | Attack Prob Upper ($\tau_{hi}$) | Attack Prob Lower ($\tau_{lo}$) | Intended Operational Use Case |
| :--- | :---: | :---: | :---: | :--- |
| **Policy A (Permissive Baseline)** | $\tau_{5\%} = 0.6001$ | 0.70 | 0.35 | High automation, low analyst workload. Minimizes abstentions. |
| **Policy B (Balanced Anomaly Guard)** | $\tau_{25\%} = 0.1873$ | 0.70 | 0.35 | **Recommended.** Catches 5.33% (104 of 1,953 flows) of held-out Bot flows via anomaly abstention while maintaining 79.20% coverage on known traffic. |
| **Policy C (Zero-Trust Guard)** | $\tau_{50\%} = 0.0558$ | 0.50 | 0.20 | Maximum safety for critical infrastructure. Requires high analyst capacity. |

## 12. Known Limitations & Research Honesty

TraceGuard is engineered around scientific integrity rather than marketing claims:

1. **Held-Out Zero-Day Failure (Ares Botnet C2):**  
   In supervised evaluation on held-out attacks, the Random Forest classifier achieved **0.00% recall** on the `Bot` family (1,953 clean flows), misclassifying all 1,953 as benign with 99.98% confidence. The Isolation Forest anomaly detector caught **5.33% (104 of 1,953 flows)** under Policy B ($\tau_{25\%} = 0.1873$), routing them to `ABSTAIN`, while 94.67% (1,849 flows) were falsely cleared as `LIKELY_BENIGN`. Even under Policy C ($\tau_{50\%} = 0.0756$), 41.07% of Bot flows continue to evade detection. Flow-level statistical metrics alone cannot reliably detect low-rate command-and-control check-ins that mimic normal web browsing.
2. **`LIKELY_BENIGN` is Not a Security Guarantee:**  
   A decision of `LIKELY_BENIGN` means the flow statistically resembles known benign baseline traffic. It does not prove the flow is harmless. Defense-in-depth requires host telemetry, authentication logs, and endpoint monitoring.
3. **Flow Features Required (No Direct Raw PCAP Ingestion):**  
   The API consumes structured 69-feature network flow records. It does not parse raw packet captures (`.pcap`) directly on the HTTP interface. Network traffic must be processed through a compatible flow exporter (e.g., CICFlowMeter) before submission.
4. **Offline Historical Drift vs. Live Telemetry:**  
   The drift analysis displayed in the dashboard represents historical day-to-day covariate shift within CIC-IDS2017, not a real-time production stream.
